# 1. Record architecture decisions

Date: 2026-08-25

## Status

Accepted

## Context

We need to record the architectural decisions made on this project, so that a decision that constrains future work can be found later with its reasoning intact, rather than reconstructed from commit messages.

## Decision

We will use Architecture Decision Records, as described by Michael Nygard, stored in `docs/adr/` and numbered sequentially.

## Consequences

Any decision that constrains future work gets an ADR. Reversing a decision means a new ADR that supersedes the old one — earlier records are never edited to match a later ruling.
